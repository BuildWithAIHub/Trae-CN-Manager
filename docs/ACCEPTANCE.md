# 0.2.2 交付验收清单

本清单用于开发者自检后由使用者逐项确认。**未勾选项表示尚未完成该项人工验收，不代表故障。模拟测试通过不能代替真实手机号登录、官方领取和系统重启测试。** 请先用独立测试数据目录和测试项目，之后再连接日常账号。

文档日期：2026-10-24。最终测试数量、构建产物校验和、EXE 自检和界面检查记录，应以本次交付的检查报告为准；本清单不预填尚未发生的真实验收结果。真实全盘扫描、物理重启、真实记忆写入及所有付费套餐均不得仅凭模拟测试勾选。

## 1. 发布包与首次运行

- [ ] 只复制 Setup EXE 到空文件夹运行，选择新的可写目录完成安装，确认不需要 Python、便携源目录或其他随附文件。
- [ ] 用安装后程序自检并打开登录界面；安装器升级保留 data，文件占用或校验失败时不报告成功。
- [ ] 完整解压 Windows x64 包，确认 EXE、运行依赖目录、许可证和说明文档都在。
- [ ] 在没有独立安装 Python 的 Windows 测试环境启动 EXE，出现密码设置界面。
- [ ] 输入短于 8 个字符的密码，确认不能创建；输入匹配且不少于 8 字符的密码后创建成功。
- [ ] 退出再打开，错误密码不能解锁，正确密码能看到原有数据。
- [ ] 切换深/浅主题，测试窗口缩放、托盘还原、锁定与闲置锁定。
- [ ] 关闭窗口后检查是否驻留托盘；使用托盘“退出”完成真正退出。
- [ ] 未启用后台设置前，确认本工具没有新建后台任务、专用后台启动项或保存 background.key。
- [ ] 升级已有版本时完整保留桌面便携目录的 data；用原密码解锁并看到原账号，未预先生成恢复码或创建空库替代原库。
- [ ] 测试自定义标题栏拖动、双击最大化/还原、最小化/关闭按钮、深浅主题，以及当前 DPI/多屏配置；窗口不能拖出后无法找回。

## 2. 安装检测与两个真实账号

- [ ] 运行诊断，核对检测到的 TRAE CN 可执行程序、版本、全局目录和默认资料位置。
- [ ] 兼容性为 baseline 时，确认界面仍提示官方结果需实际查询；其他版本显示 unverified 而非无条件兼容。
- [ ] 在默认官方窗口通过自己的手机号完成官方验证，再检测/同步账号，核对账号名称和用户身份。
- [ ] 创建第二个管理器实例，用另一个本人有权使用的手机号完成官方登录，再同步。
- [ ] 同时打开两个实例，在各自官方账号菜单核对身份；分别重启所选实例后身份仍正确。
- [ ] 验证网页登录回调没有意外登录到另一个实例。若出现问题，记录 TRAE 版本与操作步骤，不把它标记为通过。
- [ ] 修改名称与备注；从账号库移除一个测试条目，确认没有删除原 TRAE 或项目目录。
- [ ] 查询两个账号权益，对照官方仪表盘；缺失数据应显示未知，不能显示猜测的 0 或假余额。

## 3. 签到与失败状态

- [ ] 先在官方客户端确认当天活动可用性；手动签到一个测试账号，对照官方已签到状态和奖励。
- [ ] 再次签到已成功账号，应提示已完成或跳过，没有伪造额外奖励。
- [ ] 如果官方未开放活动，应显示未开放；如果已过期，应提示官方重新登录/同步。
- [ ] 断网后执行手动签到，确认显示失败，且未把该账号记为当天成功。
- [ ] 官方登录更新后“同步登录”，再次查询/签到；不把此过程称为管理器独立刷新 Token。
- [ ] 启用“解锁后自动签到”并重新解锁，核对当天已成功记录不会重复领取；关闭该选项后不自动运行。
- [ ] 默认积分刷新间隔为 15 秒；分别设置 5 秒与 300 秒、关闭自动刷新及手动查询，核对界面和保存结果。
- [ ] 对自己的购买套餐账号及有奖励账号分别比对官方数据；未有对应账号的套餐记录“未测”，不按免费账号结果推断全部套餐。
- [ ] 在官方端消费后观察轮询更新和上次成功时间；记录实际延迟，不把轮询称为服务器推送或承诺消费瞬间更新。
- [ ] 签到后确认立即刷新请求；已有成功余额时断网，确认保留上次值、标明时间和失败状态，恢复网络后更新；首次失败不能显示猜测的 0。

## 4. Windows 定时和开机补跑

- [ ] 在可控测试时段设置几分钟后的北京时间，明确勾选“后台每日签到（任务计划 / 当前用户启动项）”并保存。
- [ ] 查看设置和诊断中的实际后台方式，记录 `task` / `startup` / 待确认，不能只根据已勾选就判定注册成功。
- [ ] 若方式为 task：在任务计划程序查看对应 `TraeCNManager-*` 的每日/登录触发、当前用户、StartWhenAvailable，以及 EXE/data 路径；若为 startup，本项记录“不适用”。
- [ ] 若方式为 startup：确认 HKCU Run 下 `TraeCNManager-*-Background` 专用项指向本次 EXE、`--background` 及正确 data 目录；不要求创建任务权限，诊断不能误报任务创建成功。
- [ ] 确认 data/background.key 已创建，文件内容不是明文密码；不要把该文件上传。
- [ ] 完全退出管理器 GUI，在当前 Windows 用户仍登录的情况下等待触发，重新打开并检查日志与官方签到结果；startup 方式应有独立隐藏后台进程继续运行。
- [ ] 锁定管理器界面或锁屏后验证后台模式按预期执行；该模式无需再次输入管理器密码是已明确接受的设计。
- [ ] 测试错过每日时刻后重新开机登录，确认补跑当天，并且没有宣称补领历史日期奖励。
- [ ] 关闭后台签到并保存，确认对应任务、专用后台启动项和后台密钥被移除；空闲 startup 进程在下一次约 30 秒检查后退出，若已有操作先等待完成。
- [ ] 再次启用并验证登录后启动；单独测试“登录 Windows 时启动管家”GUI 开关，避免把两个启动项混为一项。
- [ ] 测试失败后的重试/再次手动执行，并核对日志；结束后恢复自己的正式签到时间。

## 5. MCP、Skills 与 Rules

- [ ] 建立空测试项目并加入管理器。分别选择默认实例、独立实例和项目 MCP，新建不同名称配置，确认文件位置正确且彼此独立。
- [ ] 导入带注释、末尾逗号、未知字段的测试 JSONC，保存后未知字段仍在；重名导入应拒绝且原文件不变。
- [ ] 关闭目标 TRAE 后测试 MCP 启停，确认停用配置不在活动 mcpServers 中；再启动目标 TRAE 核对实际加载状态。
- [ ] 仅对自己认可的 MCP 点击连接检测，核对 initialize/tools/list、失败提示和超时；没有点击时不能自动执行命令。
- [ ] 导出默认脱敏 MCP，检查 args/env/headers 值和 URL query 没有真实凭据；如主动完整导出，把文件按敏感文件保存。
- [ ] 新建全局 Skill，核对其他账号也可见；新建项目 Skill，核对作用域只属于该项目。
- [ ] 测试 Skill 编辑、停用后编辑、重新启用、ZIP 导出、目录/ZIP 导入、重名冲突和删除备份。
- [ ] 向导入器提供有路径穿越或缺少 SKILL.md 的测试 ZIP，确认拒绝且没有写到目标目录外。
- [ ] 用公开 GitHub 仓库首页或 ZIP 链接导入一个自己有权使用的小技能包，检查名称、资源和许可证；再用 tree 子目录链接核对只导入所选技能，不安装仓库里其他技能。
- [ ] 测试共享全局 Rules、项目 Rules 及子目录，核对停用后 TRAE 不再加载；在官方项目对话验证规则效果。
- [ ] 读取条目后用外部编辑器修改同一文件，再保存旧内容，确认出现刷新/冲突提示。
- [ ] 在测试 Skill 内新建文件/子目录、读取编辑、逐文件和目录启停/删除，确认停用资源在原生扫描目录之外；停用目录中新建子文件仍保持停用。
- [ ] 分别编辑已停用的项目 Rule 和 Skill，确认原作用域及停用状态不变；停用 SKILL.md 时整个技能停用。
- [ ] 测试选中条目与当前范围的批量启停/删除、MCP 选中/全部操作；预设重名目标或不存在条目时，不能部分保存已选结果。
- [ ] 在测试数据目录内注入一次批量操作中途失败，核对已完成步骤恢复，原文件仍在；回滚被权限阻止时应明确报错并保留备份。
- [ ] 用自己认可的公开 HTTPS/raw JSON、携带 config 的原生 mcp-import 链接导入 MCP；只有服务流或缺少完整配置的链接应说明不能导入。
- [ ] 对测试文件夹搜索常见 MCP 文件，核对搜索层级、数量限制和所选导入文件；私有/回环下载地址、内嵌凭据与 HTTP 文件应被拒绝。
- [ ] 分别导入本地/HTTPS 单 Markdown 与 HTTPS ZIP；单 Markdown 明确只含主文件，不假称已自动获取其脚本资源。
- [ ] 在测试目录迁移全局 Skills 到另一盘符的空目录，确认原生 skills 是实际联接，目标 TRAE 重新启动后能加载，管理器和原生入口内容一致。
- [ ] 预先放置同名文件，确认迁移拒绝且原内容不变；在独立测试数据中模拟复制/联接/标记保存失败，确认恢复原入口并清除本次部分复制。
- [ ] 测试切换两个自定义目录和返回默认，旧自定义目标保留；项目 Skills 路径不变，停用资源仍可恢复；不删除既有非本工具目录联接的目标。

## 6. 备份、恢复和迁移

- [ ] 为测试数据导出 `.tcmbackup`，使用不同于本机密码的迁移密码；错误迁移密码或篡改文件应导入失败。
- [ ] 在另一个空 data 目录创建新保险库并导入；账号条目被合并，本机后台设置没有被备份自动启用。
- [ ] 再导入含相同 TRAE 用户的备份，确认原有本机账号未被覆盖。
- [ ] 恢复配置前关闭目标 TRAE，放置一个冲突测试文件，恢复后该文件保持原内容。
- [ ] 为迁移项目显式选择本机目标目录；未映射项目应跳过，不按旧机器绝对路径写入。
- [ ] 从配置备份恢复一次已删除测试 Skill 或规则，并核对资源完整。
- [ ] 在备份页选择一条本机配置变更历史并回滚，确认恢复前的当前内容也生成备份，可再次恢复。
- [ ] 在第二台机器/Windows 用户上实际验证账号恢复。官方要求验证时完成官方登录再同步，不预先假定凭据永久通用。
- [ ] 修改本机密码，旧密码失效、新密码有效；已导出迁移包仍使用原迁移密码。
- [ ] 正常解锁后生成恢复码并另行保存；关闭展示窗口后不能再次查看原码，磁盘恢复文件没有明文恢复码/私钥/保险库密钥。
- [ ] 在独立测试库用错误恢复码测试失败、正确恢复码重设密码测试成功，再生成新码并确认旧码失效。
- [ ] 有后台签到和恢复码的测试库改密码后，重新启动并分别验证新密码、恢复码和后台材料一致；伴随材料准备/提交失败时应保留原文件组。
- [ ] 仅在独立测试库模拟密码更新中断 journal，重启后恢复一致状态；真实断电/磁盘损坏不作为这项测试的默认已通过结果。
- [ ] 对没有事先生成恢复码的旧测试库，忘记密码入口不能绕过原密码；数据目录入口能打开实际 data，打开文件不等于解密成功。
- [ ] 导出包含受管自定义 Skills、停用资源、当前原生记忆和已保存账号快照的加密迁移包，在空测试库导入后逐项核对；原生记忆必须再次确认合并。

## 7. GitHub 与源码发布

- [ ] 设置自己的公开 `owner/repository`；无 Release 时显示尚未发布，有新版本时只打开正确发布页。
- [ ] 上传前确认源码包不含 data、accounts.vault、recovery.json、恢复码、rotation journal、background.key、真实实例、配置备份、迁移包、私人记忆或个人截图。
- [ ] 从源码安装开发依赖，运行 `python -m pytest`、`python scripts/build.py`，再运行 EXE 的 `--self-test`。
- [ ] 检查第三方许可证随包存在，Qt/PySide 的 LGPL 说明没有被误写成整个包都按 MIT。
- [ ] 记录通过/失败/未测项目、管理器版本、TRAE 版本、Windows 版本、时间和脱敏复现步骤，再决定是否用于自己的日常账号。

## 8. 目录扫描、权限与迁移位置

- [ ] 先在独立空 data 中解锁，快速找到真实路径时只确认结果，不弹全盘授权、不自动深扫；找不到时可直接手动选择。
- [ ] 主动点击深度扫描时出现明确授权；拒绝后不自动扫描，仍可手动输入/浏览四类位置并打开定位指南。
- [ ] 同意扫描后可取消；核对约 120 秒/20 万目录限制、访问被拒绝计数和部分完成说明，不能将部分结果当作全盘完成或已取得系统权限。
- [ ] 点击当前找到/未找到/权限提示的“确定”，重新登录后相同状态不重复弹出；确认该按钮本身不替代扫描授权。
- [ ] 使用独立测试安装/资料目录模拟盘符迁移，原路径失效后先快速重新查找并重新提示，深度扫描仍由用户主动触发；确认后再次保持安静。真实日常安装不必为此强行搬迁。
- [ ] 手动粘贴带引号/环境变量的有效路径、选择非 C 盘安装与缓存，保存后核对实际使用；无效 EXE、错误用户数据根目录和不可访问目录应说明问题。
- [ ] 记录真实跨盘扫描实际覆盖范围及未读目录；未实际运行时保持“未测”，不得沿用临时目录扫描结果宣称全盘完成。

## 9. 账号记忆快照、合并与精确回滚

- [ ] 先备份真实记忆，功能验收优先使用独立 global_home/memory 的合成 Markdown；若不准备修改日常记忆，真实写入明确记录“未测”。
- [ ] 核对原生用户记忆与项目记忆路径，并验证本机同用户窗口共享；界面不能把它描述为官方云端账号隔离。
- [ ] 将当前共享记忆保存为来源账号的加密快照，核对时间和文件数；未保存快照的账号不能被假装为有效来源。
- [ ] 打开另一个账号实例时选择“不同步，直接打开”，确认未写入另一份记忆；选择来源时先显示合并预览，再经确认写入。
- [ ] 在测试记忆中准备重复段落、不同标题及现有内容，确认合并保留目标内容并去重；其他打开窗口可能读到变化的说明清楚可见。
- [ ] 测试并发外部修改、符号链接和越界路径，确认拒绝而不覆盖无关文件。
- [ ] 合并后新增一份受管测试记忆，再选择合并前历史精确回滚，确认恢复原内容并移除该历史后新建的受管文件；恢复前当前状态也保存在加密历史中。
- [ ] 加密迁移导入后，账号记忆快照按账号对应；当前原生记忆需确认合并，取消时不改本机记忆。跨电脑项目标识与实际 TRAE 加载效果单独验收。

验收反馈不需要提供短信验证码、完整手机号、Token、Cookie、后台密钥或保险库密码。日志中如仍有个人路径或敏感内容，先自行遮盖。
